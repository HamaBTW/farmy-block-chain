## 2. Smart contracts (`farmy_blockchain/`)

```
contracts/
  interfaces/IBatchRegistry.sol   shared: the only thing B imports from A
  interfaces/IFarmCoin.sol        shared: only if needed
  registry/BatchRegistry.sol      Person A: ERC-721
  payment/FarmCoin.sol            Person B: ERC-20 "FRM"
  payment/PriceCapEscrow.sol      Person B
  libraries/                      pure helpers, only if reused
  mocks/                          test-only mocks of the other person's interface
migrations/                       shared deploy scripts
test/registry · test/payment · test/integration
```

### 2.1 BatchRegistry (Person A, ERC-721)
One NFT is one physical batch. It is the source of truth for the **physical world**: who holds the
goods, whether they were checked, and the last declared price. It holds no money.

| Data | Where |
|------|-------|
| Metadata (type, origin, quantity) | off-chain JSON; only the URI/hash goes on-chain |
| Current custodian | storage (read by escrow) |
| Validation flag | storage (read by escrow) |
| Last declared price | storage (read by escrow); full history comes from `PriceRecorded` events |
| Checkpoints (weight, temp, location, inspector) | **events only**: `CheckpointAdded(batchId, dataHash, inspector)`, with `dataHash` a `bytes32` of the off-chain record |

Roles: `owner/regulator` (sets inspectors and the escrow address), `inspector` (checkpoints and
validation), `custodian` (transfers custody), `escrow` (the only caller of `recordSalePrice`).

### 2.2 FarmCoin + PriceCapEscrow (Person B, ERC-20)
The source of truth for **money and rules**. It holds no custody or inspection data.
- `FarmCoin`: OpenZeppelin ERC-20 `FRM`. v1 had a free `mint` for the demo; v2 replaces it with ETH `buy`/`sell` and a cap (see section 6).
- `PriceCapEscrow`: holds buyer FRM until delivery. It enforces
  `price <= lastPrice * (100 + maxMarkupPercent) / 100` and has an explicit sale state machine
  (`Created → Deposited → Released | Refunded`).

### 2.3 The only link: `IBatchRegistry`

```
PriceCapEscrow ──reads──►  getLastPrice(batchId)  custodianOf(batchId)  isValidated(batchId)
PriceCapEscrow ──writes─►  recordSalePrice(batchId, price)   (registry checks msg.sender == escrow)
BatchRegistry  ──never calls──► PriceCapEscrow
```

- The escrow imports the **interface**, never `BatchRegistry.sol`.
- Prices are `uint256` in FRM base units (18 decimals) on both sides.
- Deploy order: `BatchRegistry` → `FarmCoin` → `PriceCapEscrow(registry, coin)` → `registry.setEscrow(escrow)`.
- Until the other side is ready, each person tests against a mock in `contracts/mocks/`.

### 2.4 Sale lifecycle across both contracts

```
Regulator   registerAsset(farmer, Land, uri, 5000 FRM)          → AssetRegistered, PriceRecorded
Farmer      harvest(landId, uri, 1000, 1000 FRM)               → LotHarvested, PriceRecorded(1000)
Transporter transferCustody → checkpoints by inspector         → CustodyTransferred, CheckpointAdded
Inspector   checkAndValidate(id, hash)                         → CheckpointAdded, BatchValidated
Warehouse   createSale(id, 150)  ✗ reverts (cap = 120 at 20%)
Warehouse   createSale(id, 115)  ✓                             → SaleCreated
Buyer       FRM approve + deposit(saleId)                      → Deposited
Warehouse   transferCustody(id, buyer)                         → CustodyTransferred
Anyone      releasePayment(saleId): validated ✓, custodian == buyer ✓
            → FRM to seller, registry.recordSalePrice(id, 115) → PaymentReleased, PriceRecorded(115)
```

## 3. Web UI (`farmy_web/`)

```
src/
  app/                    routes (shared): layout.tsx, page.tsx, registry/page.tsx, market/page.tsx
  lib/                    shared, change with a Decisions Log entry
    chain.ts              Ganache constants (chain 1337, network 5777, RPC URL)
    contracts.ts          getContract(name, signer?) / getDeployment / getReadProvider
    wallet/WalletProvider.tsx   React context: connect, account, chainId, switch/add Ganache, getSigner
  components/             shared UI: WalletButton, ConnectionStatus
  contracts/deployments.json  GENERATED (git-ignored), { ContractName: { address, abi } }
  features/registry/      Person A screens + hooks
  features/payment/       Person B screens + hooks
  types/ethereum.d.ts     window.ethereum typing
scripts/sync-contracts.mjs  Truffle build → deployments.json (network 5777)
```

**Data flow**
- **Reads** go straight to Ganache through `getContract(name)` (a `JsonRpcProvider`), so screens work before a wallet is connected.
- **Writes** use `getContract(name, await getSigner())`, so MetaMask signs every transaction. The UI never sees a private key.
- **History** (checkpoints, price history, sales) comes from contract **events** (`contract.queryFilter`), not extra storage.
- **Rules** are enforced on-chain. The UI may pre-check (for example show the price cap) only to give a nicer message.
- Pages are thin server components that render one `"use client"` feature component (wallet access needs the browser).

**Contract → UI pipeline**

```bash
cd farmy_blockchain && npm run migrate   # truffle migrate --reset + sync-contracts
cd farmy_web && npm run dev              # predev also runs sync-contracts
```

`getContract` returns `null` for a contract that isn't deployed yet, and the screens show "not deployed" instead of crashing.

## 5. Key technical decisions

| Decision | Reason |
|----------|--------|
| solc **0.8.24**, `evmVersion: "paris"`, optimizer 200 runs | Ganache 7 doesn't support Shanghai/Cancun opcodes (`push0`, `mcopy`) |
| OpenZeppelin **5.0.2** (not 5.1+) | Newer versions use `mcopy` and fail to compile for `paris` |
| Checkpoints and price history as events | Gas: history is read off-chain only |
| UI in its own folder (`farmy_web/`) | Keeps the Truffle project contracts-only, and each side has its own `package.json` |
| ABIs/addresses generated, not committed | Addresses change on every Ganache reset or `migrate --reset` |
| ethers v6 + plain React context (no wagmi) | One local chain and one wallet; fewer dependencies |

## 6. v2 (2026-11-08, after teacher review)

Spec: [docs/superpowers/specs/2026-11-08-farmy-v2-assets-lots-ethcoin-design.md](docs/superpowers/specs/2026-11-08-farmy-v2-assets-lots-ethcoin-design.md).
The contracts keep their names and files; on screen the registry is called **Farm**. Sections 2.1, 2.2 and
2.4 above describe v1; this section says what v2 changed.

**Three kinds of token.** Every `BatchRegistry` token has a `Kind` (`Land = 0`, `Machine = 1`, `Lot = 2`).

| Kind | Created by | Function |
|------|-----------|----------|
| Land | regulator only | `registerAsset(to, Kind.Land, uri, price)` |
| Machine | regulator only | `registerAsset(to, Kind.Machine, uri, price)` |
| Lot | the holder of a Land token | `harvest(landId, uri, quantity, price)`; the lot keeps its `landId` |

`mintBatch` and `validateBatch` are gone. The inspector now calls `checkAndValidate(id, dataHash)`, which
emits `CheckpointAdded` and then `BatchValidated` in one transaction.

**Split rule.** `splitLot(lotId, quantities)` is called by the lot's custodian: 2 to 10 parts, each > 0,
adding up to the lot's quantity (`BadSplit` otherwise). Each child is a new Lot minted to the caller with
the same `landId`, `parentId = lotId` and the parent's validation flag. The parent's price is shared **in
proportion** (`parentPrice × part / quantity`, the last child takes the rounding remainder, so the parts add
up exactly), and the **parent is closed**: it can no longer be transferred, checked or sold.

**`IBatchRegistry` v2.** The interface (frozen again) gains `isActive(batchId)`, false for a closed (split)
lot. `PriceCapEscrow.createSale` refuses a closed lot with `NotActive`. If a lot is split while
it is for sale, the sale can't complete and the buyer can refund.

**FarmCoin: capped and backed by ETH.** `FarmCoin(maxSupply)` is an `ERC20Capped` with `RATE = 1000`; the
migration deploys it with a cap of 1,000,000 FRM. There is no owner and no free mint:
- `buy()` is payable: `msg.value × 1000` FRM are minted to the buyer (1 ETH = 1000 FRM).
- `sell(amount)` is `nonReentrant`: burns `amount` FRM and sends `amount / 1000` ETH back.
- `reserve()` returns the ETH held. **Invariant: `reserve() == totalSupply() / RATE`**, so every FRM is backed.

**Web app.** Farm page with Land / Machines / Lots tabs, a "Register land or machine" form (regulator),
Harvest, Split, Check and validate and Hand over in the Next step card, a family tree on each asset page, and
a Wallet card on Market to buy and sell FRM.
